# Сообщение коммита для Astra

Задача: посмотреть, что изменилось, и выдать **готовый текст** сообщения
коммита. **Не запускать `git add`, `git commit`, `git push`** — что и когда
попадает в историю, решает пользователь. Он копирует текст руками и
коммитит из IDE, поэтому в ответе не должно быть ни git-команд, ни блоков с
Run-кнопкой.

## Что сделать

1. Собрать картину изменений:

   ```
   git status --short
   git diff --stat HEAD
   git diff HEAD
   ```

   Новые файлы в `git diff HEAD` не попадают — прочитать их отдельно
   (`git status --short` покажет их как `??`).

   Если пользователь передал аргумент (`/commit-message staged`, имя файла,
   диапазон) — ограничиться этим срезом. Без аргумента брать всё
   незакоммиченное.

2. Если изменений нет — сказать об этом и остановиться.

3. **Всегда одно сообщение на весь срез.** Даже если правки не связаны между
   собой, разбивать на несколько коммитов не предлагать — за логическое
   деление истории отвечает пользователь. Несвязанные куски просто идут
   отдельными пунктами списка.

4. Не пересказывать diff построчно. Понять, **что сделано** и зачем: какую
   проблему человека или системы закрывает правка. Если это выяснялось в
   текущей сессии — использовать то, что уже известно, а не перевыводить из
   кода.

5. Выдать текст в одном фенсед-блоке без языка, чтобы его можно было
   скопировать целиком. Больше в ответе ничего нет — ни преамбулы, ни
   пояснений после, ни команд.

## Формат

```
тип(область): суть одной строкой

- сделанное дело, глаголом
- сделанное дело, глаголом
- сделанное дело, глаголом

Миграция 026 · env ASTRA_FOO · 969 тестов · ручной шаг: перезапуск docker

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

**Заголовок:** ≤ 72 знака, тип латиницей, область и суть по-русски, после
двоеточия строчная буква, точки в конце нет. Типы в ходу: `feat`, `fix`, `ui`,
`docs`, `refactor`, `test`, `chore`. Области — по-русски и по продукту, как в
истории: `профиль`, `рассылки`, `логи`, `админ-панель`, `метрики`, `аналитика`,
`таро`, `vault`. Если в срезе несколько несвязанных правок — заголовок про
главную, остальные живут в пунктах.

**Тело — тезисы, не проза.** Читается одним взглядом:

- 3–7 пунктов, маркер `-`, между заголовком и списком пустая строка;
- каждый пункт — **сделанное дело**, а не проблема: «uv ставится колесом с
  PyPI», «пол профиля добавлен в payload», а не «uv не ставился с ghcr»;
- почему так сделано — коротким хвостом после тире в том же пункте, если это
  неочевидно: «— зависимости от ghcr.io в сборке нет»;
- один пункт = одна мысль, ≤ 2 строк по 76 знаков. Не влезает — значит,
  пунктов два;
- порядок: сначала то, что человек увидит в продукте, потом внутренние
  решения, потом попутно закрытые дыры.

**Служебная строка** — последняя перед трейлером, отделена пустой строкой,
части через `·`. Собирает то, что нужно при деплое и чего нельзя пропустить:

- номер миграции Alembic и что она накатывает;
- новую переменную окружения;
- ручной шаг после деплоя;
- на чём проверено (живая база, реальный аккаунт, число тестов), если
  проверялось.

Ничего из этого нет — писать `Миграций нет`, чтобы строка стояла всегда и
глаз находил её не читая.

Трейлер `Co-Authored-By` ставить, только если правку делал я. Если пользователь
писал код сам — убрать.

## Чего не делать

- Не писать «обновлены файлы», «различные улучшения», «рефакторинг кода» —
  такой заголовок не несёт информации.
- Не перечислять имена файлов и функций вместо смысла. Имя модуля уместно, когда
  без него не объяснить решение (`users_crud.clear_birth_time`).
- Не разворачивать пункт в абзац прозы: скилл существует ради того, чтобы
  смысл коммита читался за один взгляд.
- Не выдумывать проверку, которой не было.
- Не добавлять ссылки на задачи и PR — в истории Astra их нет.
- Не давать команду `git commit` и не предлагать закоммитить.

## Пример

```
feat(спроси астрид): черты партнёра и повторяющийся сценарий

- добавлены два платных вопроса в теме «Любовь» по 1 ⭐: «Черты моего
  судьбоносного партнёра?» и «Почему я снова и снова обжигаюсь?»
- типаж (8 штук) и петля (7 штук) считаются Python по порогам, модель их
  только объясняет; пороги подобраны на 250 случайных картах
- Астрид зовёт по имени трижды за покупку, имя вставляет код при рендере;
  негодные имена отбраковываются
- пол профиля добавлен в payload обоих продуктов — раньше не доходил до
  модели, мужчина мог получить разбор в женском роде
- card_caption убран под try: исключение после списания звёзд оставляло
  человека без ответа и без возврата
- тест изоляции переписан на обход по SPECS + проверка полноты контракта

Миграции 026 и 027 · 969 тестов · оба промпта прогнаны на DeepSeek

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```
