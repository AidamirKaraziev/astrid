# Линтер видит всё, кроме бота и админки

Цель: `mypy` в `make lint` проверяет весь `src/astra`, кроме пакетов
`telegram` и `admin`, — и при этом зелёный не за счёт заглушек, а потому что
код исправлен.

Готово, когда: `make lint` зелёный, цель `lint` гоняет `mypy` по `src/astra`
с исключением только `telegram/` и `admin/`; новых `ignore_errors` и
`disable_error_code` в `pyproject.toml` нет; `uv run pytest -q` зелёный.

## Что сломано (проверено, не предположение)

### Охват куда меньше, чем выглядит

`make lint` проверяет только `services` и `natal_report`. Счёт по каждому
пакету отдельно (`uv run mypy src/astra/<пакет>`):

| ошибок | пакеты |
|---|---|
| 0 | wallet, payments, gifts, tarot, wheel, usage, text, support, referrals, points, notifications, db, business |
| 1–5 | users 1, ask 2, broadcasts 2, compatibility 2, predictions 3, astro 5, places 5, workers 5 |
| 10–17 | messaging 10, core 11, reports 12, llm 17 |
| 68–83 | admin 68, telegram 83 — **в этот круг не входят** |

Пакеты, где ходят деньги (`wallet`, `payments`, `gifts`, `tarot`), уже
чистые — их просто никто не проверял. Работа — в остальных.

### Две ошибки из списка — настоящие баги, не шум

**Трассировка роняет запуск.** `core/observability/tracing.py:28`
импортирует `setup_sentry_propagation` из
`sentry_sdk.integrations.opentelemetry`; в установленном `sentry_sdk 2.61.1`
такого имени нет. Воспроизведено:

```
configure_otel(settings с otel_enabled=True)
→ ImportError: cannot import name 'setup_sentry_propagation'
```

`configure_otel` зовётся из `configure_logging` при старте, то есть API и
воркер не поднимутся в ту же секунду, как кто-то включит `OTEL_ENABLED`.
Сейчас по умолчанию `false`, поэтому авария отложенная, а не текущая.

**PATCH профиля падает на профиле без даты рождения.** `users/routers.py:40`:
если в запросе есть `birth_time`, а даты нет ни в запросе, ни в профиле
(после миграции 029 профиль заводится без даты), вызывается
`datetime.combine(None, time)` → `TypeError` → 500 вместо 4xx.

Остальные — по виду: `date | None` в астрологических расчётах
(`astro/simple.py:43`, `astro/calculator.py:29`, `astro/synastry.py:178`),
`object` вместо модели в генерации разборов (`llm/natal_generate.py`,
`llm/compatibility_generate.py`), абстрактные типы `aio_pika` в
`messaging/publisher.py`, `rowcount` у `Result`. Какие из них баги, а какие
неточная аннотация, — выясняет работник и называет в отчёте.

## Решено до старта

- `telegram` и `admin` не берём: 151 ошибка, большая часть — `arg-type` от
  aiogram. Это отдельный круг; здесь — всё остальное.
- Цель `lint` переходит на `mypy src/astra --exclude` с исключением двух
  пакетов, а не на список включённых. Новый пакет тогда попадает под
  проверку сам, и забыть его невозможно — тот же довод, что у уведомления в
  точке вызова.
- **Заглушки.** Запрещено: `# type: ignore` без кода ошибки, `cast(Any, …)`,
  аннотация `Any` ради тишины, новые `ignore_errors` и `disable_error_code`.
  Разрешено, только когда неверен тип **библиотеки**, а не наш код: узкий
  `# type: ignore[<код>]  # шум: <библиотека> — <почему>` на одной строке.
  Каждый такой — строкой в отчёте. Почему не комментарием в
  `pyproject.toml`: заглушка на строку ловит меньше, чем заглушка на модуль,
  а `pyproject.toml` в этом круге — файл одной задачи.
- Ошибка, за которой стоит падение в рантайме, чинится вместе с тестом,
  который без правки краснеет. Ошибка-аннотация чинится аннотацией, тест не
  нужен.
- Правка, которая потребовала бы трогать файл вне своих `файлов`, не
  делается: работник называет её в отчёте.
- Задачи по пакетам не проверяют `make lint`: файл `Makefile` один, его
  держит последняя задача. Своя проверка у пакетной задачи —
  `uv run mypy src/astra/<её пакеты>`. Это урок прошлого круга: задача,
  которая ставит проверку на код, зависит от задач, чинящих код.
- В дорожке нет `.env`: тесты гоняются с
  `DATABASE_URL="postgresql+asyncpg://astra:astra@localhost:15444/astra"`.

## Не трогаем

`src/astra/telegram/`, `src/astra/admin/`. Существующие заглушки в
`pyproject.toml` (`ignore_errors` у `natal_report.models`,
`onboarding_service`, `ask_service`; `disable_error_code` у
`natal_report_service`) — их снимает следующий круг. `.env`, миграции.

### Два настоящих бага

- **Трассировка роняла бы запуск.** `configure_otel` импортировал из
  `sentry_sdk` имя, которого в установленной версии нет. Импорт стоит
  внутри функции, поэтому `ruff` его не видит, а падение наступает только
  при `OTEL_ENABLED=true` — и сразу у API и воркера. Работу удалённой
  функции код и так делал строкой ниже.
- **PATCH профиля отвечал 500** на время рождения без даты (профиль без
  даты возможен с миграции 029). Теперь 422 с причиной.

Остальные 60 ошибок оказались аннотациями. Там, где `None` в дату рождения
пройти не может только благодаря `birth_data_gate`, поставлена явная
проверка с понятной ошибкой (`require_birth_date`), а не `assert`.

### Просчёт в нарезке и в запуске

- **Двое из четырёх работников пропустили первую строку задания**
  (`git reset --hard <SHA>`) и работали на старой базе, где ещё не было ни

- Мёртвую заглушку в `astro/synastry.py:132` я передал последней задаче, а
