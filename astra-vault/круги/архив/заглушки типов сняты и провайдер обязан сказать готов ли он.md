# Заглушки типов сняты, и провайдер обязан сказать, готов ли он

Цель: в `pyproject.toml` не остаётся ни одной заглушки на модуль, а новый
LLM-провайдер, забывший `is_configured`, не создаётся вовсе.

Готово, когда: в `pyproject.toml` нет `ignore_errors` и `disable_error_code`;
`make lint` зелёный; подкласс `BaseLlmProvider` без `is_configured` падает
`TypeError` при создании, а `TracingLlmProvider` по-прежнему отвечает
голосом обёрнутого провайдера; `uv run pytest -q` зелёный.

## Что сломано (проверено, не предположение)

### Заглушки прячут восемь ошибок

Посчитано конфигом без заглушек, по всему охвату `make lint`:

| модуль | заглушка | что под ней |
|---|---|---|
| `natal_report/models.py` | `ignore_errors` | `:37` `Name "User" is not defined` — строковая ссылка в `relationship` без импорта под `TYPE_CHECKING` |
| `services/onboarding_service.py` | `ignore_errors` | `:150` пять `arg-type`: `create_profile(**profile_fields)`, где поля — `dict[str, object]` |
| `services/ask_service.py` | `ignore_errors` | `:89` `"type" has no attribute "model_validate"` — `result_model` объявлен как `type`, а не `type[BaseModel]` |
| `services/natal_report_service.py` | `disable_error_code = ["arg-type"]` | `:100` `birth_date: date \| None` уходит в `NatalSubject`, где ждут `date` |

Заглушка на модуль глушит **все** будущие ошибки этого класса в модуле, а
не только известные. Опыт прошлых кругов: `per-file-ignores F821` прятал
настоящий `NameError`, из-за которого рассылка не работала ни разу.

### `is_configured` не обязателен

`src/astra/llm/base.py` объявляет `is_configured: Callable[[], bool]`
аннотацией. Причина в комментарии там же: `TracingLlmProvider` наследует
базу и отдаёт `is_configured` внутреннего провайдера через `__getattr__`;
абстрактный метод в базе не дал бы создать обёртку, а метод с реализацией
перекрыл бы делегирование. Цена: провайдер без `is_configured` создаётся,
`mypy` молчит, падение — `AttributeError` в рантайме на первой проверке
готовности. Все пять нынешних провайдеров (`deepseek`, `openai`, `grok`,
`gemini`, `openrouter`) метод определяют; подклассов в тестах нет.

## Решено до старта

- Порядок для `is_configured`, как названо в прошлом круге: сначала
  `TracingLlmProvider.is_configured()` явно через `self._inner`, потом
  `@abstractmethod` в базе. Комментарий-объяснение в `base.py` уходит
  вместе с причиной.
- `natal_report_service.py:100`: в `astro/birth_time.py` с прошлого круга
  есть `require_birth_date()` с понятной ошибкой `BirthDateMissingError`.
  Если `None` реально не доходит (его держит `birth_data_gate`), — она, а не
  `assert`. Если доходит — это баг, и он чинится с тестом.
- `onboarding_service`: правка типом (`TypedDict` полей профиля или явные
  аргументы), а не `cast`.
- Заглушки. Запрещено: `# type: ignore` без кода, `cast(Any, …)`, `Any`
  ради тишины, новые `ignore_errors`/`disable_error_code`. Узкий
  `# type: ignore[<код>]  # шум: <библиотека> — <почему>` — только если
  неверен тип библиотеки, каждый строкой в отчёте. `warn_unused_ignores`
  включён: лишний ignore уронит `make lint`.
- Ошибка, за которой стоит падение в рантайме, чинится с тестом, который
  без правки краснеет. Ошибка-аннотация — аннотацией.
- В дорожке нет `.env`:
  `DATABASE_URL="postgresql+asyncpg://astra:astra@localhost:15444/astra"`.
  Сразу после `git reset` — `uv sync --extra dev`, иначе `uv run mypy`
  не запустится. Первой строкой подробностей отчёта — `git log --oneline -3`:
  в прошлом круге двое работников пропустили `reset` и работали на старой
  базе.

### Работник остановился, а не продавил

Первый заход задачи «Заглушки сняты» упёрся в две ошибки, корень которых
лежал вне его файлов: `users/crud.py` объявлял `create_profile(birth_date:
date)`, хотя короткий онбординг сознательно заводит профиль без даты, а
колонка nullable. Сигнатура лгала, вызов был честным. Работник не стал
глушить и не стал править чужой файл — остановился с вопросом. Я передал
ему `users/crud.py` и `ask/products.py` (вторая задача круга их не трогала)
и заодно запретил обход через `product.calc.RESULT_MODEL`: `ModuleType`
отдаёт `Any`, то есть та же заглушка, только невидимая.

Урок для нарезки: восемь ошибок я посчитал по модулям, где они
**печатались**, а не по тому, где их корень. Сигнатура в другом модуле —
обычный случай для `arg-type`.

### Не баг, но защищено

`natal_report_service.py:100` — `None` в дату рождения не доходит:
`begin_self_natal_flow` стоит за `ensure_birth_data`. Вместо `assert` —
`require_birth_date()` с понятной ошибкой; если когда-нибудь дойдёт
(устаревшая кнопка подтверждения после очистки даты), человек получит
внятный отказ, а не `TypeError`.
