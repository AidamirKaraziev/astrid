# Натальная карта снова собирает PDF

Цель: разбор, заказанный в боте, доходит до человека, а не падает молча на
последнем шаге.

Готово, когда: `uv run pytest -q tests/test_natal_pipeline.py` зелёный на
настоящей модели `NatalReport`, полный прогон не пропускает интеграционные
тесты, и `make lint` ловит обращение к несуществующему полю ORM.

## Что сломано (проверено, не предположение)

`src/astra/services/natal_report_service.py:266` обращается к
`report.user_id`; в модели поле называется `owner_user_id`. В базе лежит
разбор со `status=failed` и `failure_reason: 'NatalReport' object has no
attribute 'user_id'`. Строку внёс `e9d468e feat(приглашения)` от 11 авг.

Тест `tests/test_natal_pipeline.py` зелёный, потому что `report` в нём —
`AsyncMock`: у мока есть любой атрибут. Варнинг pytest на эту строку был,
но варнинги никто не читает.

## Решено до старта

- Проверка натальной карты — машинная, тестом на живой модели. Живой разбор
  в боте человек гоняет сам, задачей круга это не оформляется.
- `mypy` включаем нестрого и **не на весь проект**: цель не нулевой счётчик
  ошибок, а чтобы класс «обращение к несуществующему полю» ловился машиной.
  Стартовый охват — `src/astra/services/` и `src/astra/natal_report/`,
  расширяем потом отдельной работой.
- `tests/conftest.py` не должен зашивать порт БД: правильный DSN приезжает
  из окружения. Работник в дорожке `.env` не видит (файл в `.gitignore`),
  поэтому в командах проверки DSN задан явно.
- Порча `spec/backlog.md` в круг не входит: она не закоммичена, работник
  получает чистый файл. Человек возвращает его сам:
  `git checkout -- spec/backlog.md`.
- Других падений нет: `tarot_readings`, `compatibility_reports`,
  `ask_readings`, `payments`, `gifts` в базе чисты. Баги, которые человек
  увидит глазами в боте, приедут отдельным кругом.

## Не трогаем

Ничего не закрыто — человек решил не ограничивать работников по файлам.
Общее правило в силе: задача правит только свои файлы из списка ниже.

## Задачи

### Натальная карта собирает PDF
кому: работник бэк · файлы: src/astra/services/natal_report_service.py, tests/test_natal_pipeline.py
готово, когда: сервис берёт `owner_user_id`; в тесте сборки PDF вместо `AsyncMock` стоит настоящий экземпляр `NatalReport` с заполненным `owner_user_id`, тест проверяет, что файл PDF создан и разбор перешёл в `ready`; подмена `report` моком в этом тесте не осталась
проверка: uv run pytest -q tests/test_natal_pipeline.py

### Тесты видят настоящий Postgres
кому: работник бэк · файлы: tests/conftest.py
готово, когда: зашитого `5432` в файле нет, DSN берётся из окружения; при заданном `DATABASE_URL` ни один тест не пропускается с причиной «Postgres недоступен», а без него подсказка «подними инфраструктуру» остаётся
проверка: DATABASE_URL="postgresql+asyncpg://astra:astra@localhost:15444/astra" uv run pytest -q -rs 2>&1 | grep -c "Postgres недоступен" → 0

### Линтер ловит несуществующее поле
кому: работник бэк · файлы: pyproject.toml, Makefile
готово, когда: `make lint` гоняет `ruff check` и `mypy` и проходит зелёным; если в `natal_report_service.py` вернуть `report.user_id`, `make lint` падает с ошибкой про отсутствующий атрибут
проверка: make lint

Проверено на объединении всех трёх ветвей, не по отчётам:

- `make lint` → `ruff: All checks passed`, `mypy: Success: no issues found in 31 source files`
- вернуть `report.user_id` → `mypy` даёт 3 ошибки `attr-defined`, `make lint` падает, тест падает

### Просчёт в нарезке

Критерий задачи «Линтер ловит несуществующее поле» (`make lint` зелёный)
в изолированной дорожке выполнить было нельзя: линтер падал ровно на том
баге, который чинила соседняя задача. Зависимость `· после «Натальная
карта собирает PDF»` я не проставил. Работник это назвал прямо в отчёте,
а не подогнал результат. На будущее: задача, которая ставит проверку на
код, зависит от задач, чинящих этот код.

### Остались недочёты, не входившие в круг

Чтобы `make lint` стал зелёным, работник заглушил настройкой реальные
замечания текущего кода: `per-file-ignores F821` для двух файлов,
`ignore_errors` для трёх модулей, `disable arg-type` для
`natal_report_service`, `follow_imports=skip` для `astra.llm.base` (там
нет `is_configured`). Это долг, а не решение — отдельной работой.
