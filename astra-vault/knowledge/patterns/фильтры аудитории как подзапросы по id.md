# Фильтры аудитории как подзапросы по id

Аудитория рассылки собирается не одним монструозным JOIN, а набором независимых
выборок `select(User.id).where(...)`, которые складываются пересечением и
вычитанием:

```python
query = select(User).where(User.bot_blocked_at.is_(None))
for include in _include_queries(criteria):
    query = query.where(User.id.in_(include))
for exclude in _exclude_queries(criteria):
    query = query.where(User.id.notin_(exclude))
```

## Почему так

- каждый фильтр пишется и читается отдельно, независимо от остальных;
- новый фильтр — это новая функция, а не правка общего запроса;
- «все, кроме тех, кто уже покупал» получается бесплатно: тот же подзапрос,
  но через `notin_`;
- условия из разных таблиц (профиль, платежи, активность, колесо) не тянут за
  собой каскад join'ов и дублей строк.

## Что важно не забыть

Заблокировавшие бота отсеиваются **всегда**, вне зависимости от фильтров: слать
им бессмысленно, а в статистике они создают видимость охвата, которого нет.

Отдельный случай — знак зодиака: считается по месяцу и дню рождения, и Козерог
переваливает через новый год, поэтому у него границы соединяются через `or_`,
а у остальных — через `and_`.

Тот же приём годится для любой «выборки людей по признакам»: сегменты для
метрик, экспорт, точечные акции.
