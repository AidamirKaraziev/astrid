# Отказ называет причину, а не молчит

Сценарий, который может не сработать, возвращает не `None`, а перечисление
причин. У каждой причины есть текст для человека, и у текста есть тест на
полноту.

```python
class GiftRefusal(StrEnum):
    UNKNOWN_CODE = "unknown_code"
    ALREADY_REDEEMED = "already_redeemed"
    REVOKED = "revoked"
    NOT_A_NEWCOMER = "not_a_newcomer"
    SELF_GIFT = "self_gift"

_REFUSAL_TEXTS: dict[GiftRefusal, str] = {...}

def refusal_text(refusal: GiftRefusal) -> str:
    return _REFUSAL_TEXTS[refusal]
```

```python
def test_every_refusal_has_words_for_a_human() -> None:
    for refusal in GiftRefusal:
        assert refusal_text(refusal).strip()
```

## Почему так

Человек нажал «Забрать подарок» и получил главное меню — он читает это как
поломку бота, а не как «подарок не для тебя». Дальше он идёт к тому, кто
подарил, и тот тоже ничего не понимает: со своей стороны он всё сделал.

Одна причина на все случаи не годится. «Мы уже знакомы», «эту ссылку уже
забрали», «это твоя же ссылка» требуют разных действий от человека, и общий
текст не подсказывает ни одного. Порядок проверок при этом важен: своя ссылка
ловится раньше «не новичок», иначе даритель, ткнувший в собственную ссылку,
получит общий отказ вместо настоящей причины.

Тест на полноту нужен потому, что новая причина без текста падает `KeyError`
уже перед человеком, а не на ревью.

## Что важно не забыть

**`StrEnum` — это строка.** Функция, возвращающая `str | GiftRefusal | None`,
не разбирается проверкой `isinstance(outcome, str)`: она поймает и отказ тоже,
и строка `"not_a_newcomer"` уедет в поле кода. Проверять отказ **первым**:

```python
if isinstance(outcome, GiftRefusal):
    ...
else:
    code = outcome
```

**Отказ не сжигает ресурс.** Ни одна причина не меняет статус подарка: ссылка
остаётся годной для того, кому предназначалась.

**Одна причина на одно место в коде — мало.** У подарка две точки проверки
(вход по ссылке и активация в конце онбординга), и развести причины надо в
обеих: [[отозванный подарок отвечал новичку что его уже забрали]].

Приём применим везде, где сценарий обрывается тихо: тосты на callback без
пользователя, кнопки от прошлого экрана, товар, ушедший из витрины между
показом и нажатием.
