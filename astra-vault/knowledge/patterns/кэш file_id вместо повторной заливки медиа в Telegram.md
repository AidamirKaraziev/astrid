# Кэш file_id вместо повторной заливки медиа в Telegram

## Проблема

Bot API каждый раз заново заливает локальный файл (`FSInputFile`), если передавать его напрямую — медленно и тратит трафик, особенно для медиа, которое отправляется многим пользователям с одним и тем же содержимым (например, приветственное видео при онбординге).

## Решение

Telegram позволяет переслать уже загруженный файл по его `file_id` — без повторной передачи байтов, почти мгновенно.

1. Первая отправка — `FSInputFile(path)`, из ответа (`Message.video.file_id` / `.photo[-1].file_id` / `.document.file_id`) забираем `file_id`.
2. Сохраняем `file_id` в Redis без TTL (ключ вида `astra:telegram:<name>_file_id`).
3. При следующих отправках сначала проверяем кэш — если есть, передаём строку `file_id` напрямую вместо `FSInputFile`.

Короткоживущий `Redis.from_url(...)` клиент на вызов — тот же паттерн, что в `services/prediction_pending.py`.

## Когда не подходит

- Если файл может меняться (нужна инвалидация кэша при обновлении контента — тогда класть версию/хэш файла в ключ).
- `file_id` привязан к конкретному боту — при смене токена бота кэш нужно сбросить.

## Пример

`src/astra/telegram/handlers/start.py` — приветственное видео для новых пользователей (`_get_cached_welcome_video_file_id` / `_cache_welcome_video_file_id`).
