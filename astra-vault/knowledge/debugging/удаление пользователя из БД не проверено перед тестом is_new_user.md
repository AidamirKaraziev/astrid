# Удаление пользователя из БД не проверено перед тестом is_new_user

## Симптом

Реализовали отправку приветственного видео только для нового пользователя (`is_new_user = user is None` в `telegram/handlers/start.py`). Ручной тест: удалил свою строку в `users`, зашёл в бота, нажал `/start` — получил обычный текст без видео, как для старого пользователя.

## Причина

Строка пользователя на самом деле не была удалена — прямой запрос в Postgres (`docker compose exec postgres psql ...`) показал ту же запись с `created_at` за месяц до теста. То есть DELETE не применился (не туда, не закоммитился, или тестировали не ту базу/окружение), а не то, что логика `is_new_user` в коде сломана.

Заодно проверили: все FK на `users` (`profiles`, `predictions`, `referral_codes` и т.д.) — `ON DELETE CASCADE`, так что само по себе удаление строки не должно падать на ограничениях.

## Урок

Перед тем как делать вывод «фича не сработала» на основании ручного изменения БД — **проверить фактическое состояние строки после операции** (`SELECT ... WHERE telegram_id = ...`), а не полагаться на то, что DELETE прошёл. Особенно если окружений (локальный docker / деплой на deadtiger) несколько и легко перепутать, к какой базе подключён клиент.
