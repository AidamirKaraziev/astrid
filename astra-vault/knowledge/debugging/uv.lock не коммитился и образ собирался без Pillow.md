# uv.lock не коммитился и образ собирался без Pillow

Заметили случайно: `git status` месяц показывал `M uv.lock`. В диффе ровно две
строки — про `pillow`.

## Что произошло

`pillow` добавили в `pyproject.toml` вместе с карточками «Спроси Астрид»
(`c5523bb`, 28 июля), `uv` пересчитал лок при первом же запуске, но в коммит
ушёл только `pyproject.toml`.

Dockerfile ставит зависимости через `uv sync --frozen` — то есть **строго по
локу, без пересчёта**. В закоммиченном локе Pillow не было, значит в прод-образе
его тоже не было, и `from PIL import Image` в `astra/ask/card.py` падал при
первой же отрисовке карточки после оплаты.

## Почему не всплыло раньше

- CI ставит зависимости через `uv sync --all-extras` **без** `--frozen` —
  раннер спокойно доразрешает Pillow сам, тесты зелёные;
- локально лок актуальный, всё работает;
- импорт спрятан внутрь функции, поэтому приложение стартует нормально —
  ломается только в момент отрисовки карточки.

## Проверка

```
docker compose exec api python -c "import PIL; print(PIL.__version__)"
```

## Вывод

Лок-файл коммитится **тем же коммитом**, что и `pyproject.toml`. Стоит заменить
в CI `uv sync --all-extras` на `uv sync --locked` — тогда расхождение уронит
сборку сразу, а не всплывёт на проде через две недели.
