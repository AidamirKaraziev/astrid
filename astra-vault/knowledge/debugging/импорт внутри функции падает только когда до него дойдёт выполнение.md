# Импорт внутри функции падает, только когда до него дойдёт выполнение

## Что нашлось

`core/observability/tracing.py`, функция `configure_otel`:

```python
from sentry_sdk.integrations.opentelemetry import (
    SentryPropagator, SentrySpanProcessor, setup_sentry_propagation,
)
```

В установленном `sentry_sdk 2.61.1` имени `setup_sentry_propagation` нет.
`configure_otel` зовётся из `configure_logging` при старте и API, и воркера,
но выходит сразу, если `OTEL_ENABLED=false`. Поэтому прод живёт, а первая же
попытка включить трассировку уронит оба процесса на старте с `ImportError`.

Чинилось удалением: эту же работу (поставить `SentryPropagator` глобальным
textmap) код делал строкой ниже через `set_global_textmap`.

## Почему никто не видел

- Импорт стоит **внутри** функции — ленивый, ради того, чтобы не тянуть
  OpenTelemetry, когда он выключен. Модуль импортируется без ошибок.
- `ruff` (`F82`) ловит неопределённые имена, но не проверяет, есть ли имя в
  чужом модуле.
- Тест на `configure_otel` был только с `otel_enabled=False`.
- Выключенная по умолчанию ветка не исполнялась нигде: ни в тестах, ни на
  проде.

Поймал `mypy`, как только пакет `core` попал под проверку: `Module ... has no
attribute "setup_sentry_propagation"  [attr-defined]`.

## Правило

**Ветка за флагом, выключенным по умолчанию, — непроверенный код, пока на
неё нет теста с включённым флагом.** Ленивый импорт внутри такой ветки
делает её ещё и невидимой для импорта модуля. Против этого класса работают
две вещи: `mypy` с `attr-defined` по всему пакету и тест, который включает
флаг.
