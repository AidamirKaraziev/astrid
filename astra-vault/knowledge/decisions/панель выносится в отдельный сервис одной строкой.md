# Панель выносится в отдельный сервис одной строкой

Админ-панель живёт внутри сервиса `api`, но собрана так, что переезд в свой
контейнер стоит двух правок: убрать `include_router(admin_router)` из
`astra.main` и поднять `astra-admin` из того же образа.

## Почему сейчас внутри api

Те же модели, та же сессия, тот же конфиг. Отдельный сервис ради одной
страницы, которую открывают раз в неделю, — это дублирование инфраструктуры
без выигрыша.

Оговорка не про слои, а про процесс: в `api` вместе с HTTP крутятся polling
бота и воркер уведомлений, и панель делит с ними event loop. Поэтому всё
тяжёлое (рассылки, агрегаты) уходит в воркер, а панель только ставит задачу.

## Что держит шов открытым

- `astra.admin.app:create_admin_app()` — самостоятельное приложение со своим
  lifespan (поднимает только базу) и точкой входа `astra-admin`;
- сервис `admin` в `docker-compose.yml` под профилем `admin` — готов, но не
  запускается;
- префикс `/admin` живёт в самом роутере, поэтому адрес после переезда не
  меняется, только порт;
- **тест разбирает импорты модулей панели через `ast`** и падает, если кто-то
  притащит `aiogram` или `astra.telegram`. Именно это зарастает первым: один
  импорт ради «отправить человеку сообщение» — и панель больше не отделяется.

Из-за этого правила подписи кнопок рассылки вынесены в `broadcasts/sections.py`
без aiogram, а callback-и знает только воркер.

## Когда разделять

Когда у API появится публичный адрес под вебхук оплаты картами: панель должна
оказаться в контейнере, слушающем только tailscale-интерфейс, чтобы `/admin`
физически не существовал на публичном порту.
