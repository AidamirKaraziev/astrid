# Учёт прогресса ведётся журналом, а не сканированием

Состояние проекта — что сделано, что осталось, сколько стоило — собирается из
трёх файлов, которые пополняются в момент закрытия этапа: `.claude/plan/`,
`.claude/ledger.jsonl`, `.claude/handoff.md`. Скилл `/status` читает только их
и укладывается в 4k токенов.

Ретроспективное сканирование репозитория рассматривали и отклонили.

## Почему

Разрез трат по областям — сколько ушло на бэк, промпты, инфраструктуру —
невыводим из транскриптов. В сессии нет поля «это была работа над инфрой», и
восстановить его задним числом можно только догадкой по диффу. Разметка в
момент, когда контекст ещё живой, стоит одну строку JSON и не врёт.

Второе: время и токены считают скрипты (`lib/spend.py`, `lib/counters.py`),
а не модель. Джойн `session_id` из журнала с транскриптами Claude Code даёт
точные цифры за ноль токенов контекста. Модель получает готовую таблицу и
только раскладывает её по экрану.

Третье: у каждого факта один владелец. Этап живёт в подплане эпика, roadmap
хранит счётчик `n/m`, статус течёт только снизу вверх. Дублей нет — значит,
и расходиться нечему.

## Цена решения

Забыл вызвать `/stage-end` — работа выпала из статистики. Такие сессии видны
отдельной строкой «вне учёта», но восстановить их область уже нельзя.

Учёт стартует с нуля: 39 сессий, накопленных до внедрения (46 ч, 73M свежих
токенов), остаются неразмеченными навсегда.

Дисциплина держится на человеке. Автоматика ловит только то, что закрыто через
скилл.

## Когда вернёмся

Если доля «вне учёта» перевалит за треть — значит, ритуал не прижился, и
надо не чинить дисциплину, а упрощать закрытие этапа.
