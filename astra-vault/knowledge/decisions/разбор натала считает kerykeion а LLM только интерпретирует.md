# Разбор натала считает kerykeion, а LLM только интерпретирует

Продукт «Разбор натала» (`src/astra/natal_report/`, отчёт —
`src/astra/reports/natal/`). Код на `main`, ветка `feature/natal-report` слита
и удалена. В каталог товаров продукт пока не выставлен.

## В чём отличие от конкурентов

Конкуренты (Natalon, Астарио) отдают текст уровня гороскопа из паблика.
Наш дифференциатор — два конкретных приёма:

1. **PDF с колесом карты** — рисуется своим кодом (`reports/natal/wheel.py`,
   `glyphs.py`), а не берётся картинкой из сервиса.
2. **Методологический промпт:** иерархия факторов, синтез вместо перечисления,
   явный запрет Barnum-фраз («вы бываете и уверенным, и сомневающимся»).

## Разделение ответственности

Астрологию считает **Python** (`kerykeion`, `src/astra/astro/calculator.py`):
позиции, дома, аспекты. **LLM только объясняет** уже посчитанное. Тот же
принцип, что в [[сколько судьбоносных партнёров считает Python а объясняет LLM]]
и [[Split Contract LLM и Pydantic для совместимости]] — иначе на повторной
покупке модель выдаст другие числа.

## Грабли: глифы планет в PDF

PT Sans не содержит астрологических символов — планеты рендерились как
`.notdef` (пустые прямоугольники). Решение живёт в `reports/natal/fonts.py`:
отдельный шрифт с глифами (AstroGlyphs / DejaVuSans) подключается только под
символы, основной текст остаётся на PT Sans.

Связано: [[пайплайн совместимости промпт LLM PDF worker]] (архитектурный
образец), [[текущие приоритеты]] (монетизация натала — открытый пункт).
