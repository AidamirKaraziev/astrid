# Приветственное видео Astrid для новых пользователей

Связано: [[reply-меню Telegram обновляется через AutoKeyboardMiddleware]]

## Сделано

### Тексты для бота
Придуманы варианты short description / About / приветствия `/start` для BotFather с учётом реального меню бота (предсказание дня, совместимость+PDF, натал/таро/месяц — пока заглушки до монетизации). В код не идут — только для ручной настройки через BotFather.

### Видео в приветствии, только для новых пользователей
- `src/astra/telegram/handlers/start.py`: `is_new_user = user is None` — определяется до создания записи в БД (единственный надёжный признак «первый вход»), не путать с `onboarding_completed`.
- Новым пользователям `/start` шлёт `answer_video` с приветственным текстом в caption вместо обычного `answer(...)`. Возвращающиеся, `/menu`, `restart` — как раньше, только текст.
- Файл лежит в `src/astra/telegram/static/welcome.mp4` (папка ранее была зарезервирована, но не использовалась).

### Оптимизация загрузки видео
Найдено: исходный ролик — 9.6 МБ при битрейте **15.3 Мбит/с** на 5 секунд (абсурдно много для мессенджера).

1. **Сжатие**: `ffmpeg -c:v libx264 -crf 23 -preset slow -vf scale=720:-2 -movflags +faststart -c:a aac -b:a 96k` → 904 КБ (в 10.7 раза меньше), визуально без потери качества. `+faststart` — moov atom в начале файла, чтобы Telegram-клиент мог начать проигрывание до полной загрузки.
2. **Кэш `file_id` в Redis** (`astra:telegram:welcome_video_file_id`, без TTL): первый новый пользователь после деплоя/рестарта — заливка с диска (`FSInputFile`), `file_id` из ответа Telegram сохраняется в Redis. Все следующие — отправка по `file_id`, без повторной заливки байтов (мгновенно). Паттерн — как в `services/prediction_pending.py` (короткоживущий `Redis.from_url` клиент на вызов).

→ [[кэш file_id вместо повторной заливки медиа в Telegram]]

## Разобранный баг

Тестировали `is_new_user`: пользователь вручную удалил свою строку в `users`, зашёл в бота — видео не пришло, только текст.

Причина — не в коде бота. Прямой запрос в Postgres показал, что строка пользователя (`telegram_id=864185115`, `aid_kara`) всё ещё существует с `created_at = 2026-06-01` (не сегодня) — значит удаление не применилось (не туда/не закоммитилось/другая база), а не то, что видео не отправилось при реально новом пользователе. Проверили заодно: все FK на `users` — `ON DELETE CASCADE`, так что само по себе удаление не должно было упасть.

→ [[удаление пользователя из БД не проверено перед тестом is_new_user]]

## Не сделано / на потом

- Файл `welcome.mp4` (904 КБ) закоммичен как обычный бинарник, без Git LFS — ок для одного файла, но если приветственных медиа станет больше, подключить LFS.
- Ручная проверка на реальном Telegram-аккаунте после пересборки (`make up`) — не делал сам, нет доступа к боевому боту.
- Тексты для BotFather (short description / About) — не применены, лежат в чате, нужно вручную вбить через `/setdescription`, `/setabouttext`.
